# F3. 디렉토리 구조와 링크 (R3)

관련: [02 데이터 모델](../02-data-model.md), [F5 문서 화면](F5-page-view.md), 단계 [M2](../phases/M2-read.md), [M4](../phases/M4-organize.md)

## 1. 모델

| Wiki.js | 신규 |
|---------|------|
| path 문자열이 계층 결정, 가상 폴더 존재 | `parent_id` 계층. 모든 노드는 문서 (하위가 있으면 폴더 역할) |
| 페이지/폴더 같은 경로 충돌 | 구조상 불가 |
| 이동 시 링크 깨짐 | 이동 시 역링크 자동 갱신 + 이전 경로 alias 리다이렉트 |
| 정렬 이름순 고정 | `sort_order` 수동 정렬 |

slug 규칙: 기본값은 제목. `/ # ? | [ ]` 금지, 앞뒤 공백 제거, 형제 간 중복 불가.

본문이 비어 있는 문서는 하위 문서 카드 목록을 자동 표시한다.

## 2. URL

| 용도 | 형식 |
|------|------|
| 문서 (정규) | `/w/{path}` (예: `/w/nems/고도화/통계`) |
| 영구 링크 | `/p/{id}` → 정규 URL 302 (`#앵커` 유지, 휴지통·삭제 문서는 404). 복사 버튼은 [F5](F5-page-view.md) 2.1절 |
| 원문 | `/w/{path}.md` (text/markdown, 에이전트·curl용) |
| 편집 | `/edit/{path}`, `/edit/{path}?section=n` |
| 역사 | `/history/{path}` |
| 역링크 | `/backlinks/{path}` |
| 레거시 | `/{wikijs-path}`, `/ko/{wikijs-path}`, 이동 전 `/w/{old}` → `page_aliases` 조회 후 301 |

## 3. 위키 링크 문법

| 문법 | 의미 |
|------|------|
| `[[nems/고도화/통계]]` | 절대 경로, 표시 텍스트 = 마지막 세그먼트 |
| `[[nems/고도화/통계\|통계 문서]]` | 표시 텍스트 지정 |
| `[[nems/고도화/통계#개요]]` | 섹션 링크 |
| `[[/하위]]` | 현재 문서의 하위 문서 |
| `[[../]]`, `[[../형제]]` | 상위, 형제 문서 |

규칙:
1. 해석 순서: 경로 일치 → alias 일치 → 미해결(레드 링크)
2. 코드블록·인라인 코드 내부의 `[[ ]]`는 링크로 처리하지 않음 (bash `[[ ]]` 보호)
3. 상대 링크는 저장 시 절대 경로로 정규화해 `page_links.target_path`에 기록 (본문 원문은 유지)
4. 레드 링크 클릭 → 해당 경로로 새 문서 작성 화면 (중간 경로 부재 시 함께 생성할지 확인)
5. 클라이언트 렌더러는 문서 조회 응답에 포함된 링크 해석 결과(`links: {target_path → 존재 여부, 정규 경로}`)로 색상 결정

## 4. 이동 / 이름 변경

트랜잭션 순서:
1. 순환 검사 (대상 부모가 자기 하위면 거부)
2. 대상 문서와 하위 트리 `path` 갱신
3. 변경 전 경로 전부 `page_aliases` 등록 (기존 alias 중 새 경로와 같은 것은 삭제)
4. `page_links`로 참조 문서 조회 → 본문의 해당 링크 경로 치환 → 리비전 `action='link-updated'`, `source='system'`
5. 대상 문서 리비전 `action='moved'`

## 5. 트리 UI (좌측 사이드바)

- 전체 트리 표시 (이전 서비스의 "현재 디렉토리만" 방식 폐기)
- 전체 트리 1회 로드 (`/api/v1/tree?depth=20`, M2 실측 약 200노드·22KB·4ms. 지연 로딩보다 단순하고 필터에 유리), 펼침 상태 localStorage 기억, 현재 문서 자동 펼침
- 상단 필터 입력 (제목 부분 일치)
- 드래그 앤 드롭: 순서 변경, 부모 변경 (EDITOR 이상)
- 컨텍스트 메뉴: 하위 문서 추가, 이름 변경, 이동(대화상자), 휴지통
- 상단 breadcrumb (상위 문서)

## 6. 휴지통

- 삭제 = `deleted_at` 설정, 하위 문서 포함 여부 확인
- 30일 경과 시 스케줄러가 영구 삭제 (첨부 파일 포함)
- 관리자 복원·즉시 영구 삭제: [F12](F12-admin.md) 6절 (원 경로 점유 시 새 slug 입력). 삭제자는 `pages.deleted_by`에 기록

## 7. API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/v1/tree?parentId=&depth=` | 트리 노드 (id, title, path, childCount) |
| GET | `/api/v1/pages/by-path?path=` | 문서 + 링크 해석 결과 + 분류 + 첨부 요약 |
| GET | `/api/v1/pages/{id}/backlinks` | 역링크 |
| POST | `/api/v1/pages/{id}/move` | `newParentId?`, `newSlug?`, `sortOrder?` |
| DELETE | `/api/v1/pages/{id}` | 휴지통 이동 |
| GET/POST/DELETE | `/api/v1/admin/trash`, `…/{id}/restore`, `…/{id}` | 관리자 ([F12](F12-admin.md) 14절) |

## 8. 완료 기준

| 항목 | 기준 |
|------|------|
| 이동 후 링크 | 참조 문서 본문 링크가 새 경로로 치환, 레드 링크 0 증가 |
| 옛 URL | 이동 전 URL 301 → 새 경로 |
| 순환 | 자기 하위로 이동 시 거부 |
| 코드블록 | bash `[[ -f x ]]`가 링크로 렌더되지 않음 |
